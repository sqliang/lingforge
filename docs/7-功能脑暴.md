# 灵构 LingForge 综合平台 · 功能脑暴（第二批候选）

> 版本：1.0（脑暴稿，待 review）
> 定位：在 [6-综合平台升级评估方案](./6-综合平台升级评估方案.md) 确定的 ChatBot / DeepResearch / Coding Agent 三功能之外，脑暴「还能做什么」。本文**广度优先**：候选不等于承诺，入选与否、何时做，留待 review 后进入正式评估流程。
> 约束：不从技术出发找问题（避免「我有 SSE 所以什么都做成实时」），而从日常工作/生活的核心痛点出发，再回来看 AI Agent 是否是最优解、平台底座是否接得住。

## 0. 脑暴说明

- **与 docs/6 的关系**：docs/6 是「已定方向的评估与实施建议」；本文是「未定方向的开放脑暴」。两者不冲突——docs/6 的四期路线不变，本文的候选只有在通过筛选（§3）并被 review 采纳后，才会排入 docs/6 第 4 期之后的路线。
- **脑暴纪律**：每个候选必须回答「痛点是否真实存在且高频/高痛」，答不上来的直接淘汰；宁可 18 个候选砍掉 14 个，也不要 18 个都「有点意思」。
- **不确定性诚实标注**：凡涉及外部依赖（数据源、第三方 API、合规）的候选，明确写出风险，不假装可行。

## 1. 思考框架：痛点 × AI 能力 × 平台底座

### 1.1 三维筛选

一个候选值得做，需要三个维度同时过关：

```text
        痛点真实（工作/生活中反复出现、现有工具解决得不好）
          ×
        AI 适配（Agent/LLM 确实比传统软件做得好，不是硬套 AI）
          ×
        底座复用（Run/SSE/Artifact/编辑器/审批门能承接，不为它单建一套）
```

只过两维的典型失败模式：痛点真实 + AI 适配，但需要一个全新底座（如完整邮箱客户端）→ 实施成本爆炸；AI 适配 + 底座复用，但痛点是想象出来的 → 技术自嗨。

### 1.2 痛点地图

从「一个开发者/知识工作者的一天」出发梳理，而非从产品目录出发：

```text
工作面                                      生活面
─────────────────────────────────          ─────────────────────────────────
P1 信息过载：订阅源/RSS/群聊/行业动态        L1 生活琐事散落：证件到期、订阅扣费、
   看不完，又怕错过关键信息                     保修、体检，没人替你记着
P2 文书负担：周报/纪要/邮件/总结，            L2 决策疲劳：买东西比价、旅行做攻略、
   内容在脑子里，变成文字很痛                    选课选保险，信息搜集成本远高于决策本身
P3 知识散落：笔记/收藏/聊天记录里             L3 重要文件看不懂：合同、保单、账单、
   有大量「存了等于没存」的内容                  说明书，生怕踩坑又读不进去
P4 职业成长焦虑：面试准备、技能树、            L4 计划执行断层：健身/读书/学习计划
   学习计划，缺乏个性化陪练与反馈                 做了就废，缺外部节奏与复盘
P5 开发者日常损耗：PR review、依赖升级、      L5 家庭协作：共享清单、分工、提醒，
   报错排查，重复且打断心流                      靠吼和记忆力
─────────────────────────────────          ─────────────────────────────────
横切痛点 X：「搜集→整理→成文」这条链路在 P1/P2/P3/L2/L3 中反复出现——
            它正是 Agent（检索+归纳+生成）的主场，也是本平台的天然赛道。
```

## 2. 候选功能池（20 个，按主题簇分组）

> 卡片格式：痛点 → 功能形态 → AI/Agent 角色 → 底座关系 → 量级（S≲1 周 / M≈1–2 周 / L>2 周）→ 不确定性。

### 簇 A · 信息过载与决策（对应 P1）

**A1. 个人晨报 Agent**
- 痛点：每天打开 5+ 信息源扫一遍，80% 是噪音，又怕错过那 20%。
- 形态：定时（如每天 8:00）聚合用户配置的订阅源（RSS/新闻/arxiv/GitHub Trending/指定关键词），生成一份「晨报」Artifact：GenUI 卡片排版（必看 3 条 / 速览 10 条 / 可忽略摘要），可点击「这条深入研究」直接发起 DeepResearch。
- Agent 角色：定时触发的检索+摘要 Agent；去重、重要性排序、一句话理由。
- 底座关系：新增「定时触发 Run」（cron → 入队 research/chat Run）；晨报=新 Artifact 类型（复用 GenUI 渲染）；SSE 不需要（离线生成，用户来了看成品）。
- 量级：M。不确定性：订阅源质量参差，需要源管理 UI；定时任务是新基础设施（worker 定时器/外部 cron）。

**A2. 关键词哨兵（轻量监控）**
- 痛点：关心某个小众主题（如「某开源库发版」「某竞品动态」），没有现成监控工具。
- 形态：用户登记「关键词 + 频率 + 投递方式」，Agent 定期检索，命中且与历史不重复时生成提醒卡片进入会话/晨报。
- Agent 角色：复用晨报的检索+去重，是 A1 的特化。
- 底座关系：与 A1 共享定时基础设施；提醒=GenUI Callout 卡片。
- 量级：S（在 A1 之后）。不确定性：与 A1 功能重叠，可考虑合并为「晨报 + 订阅规则」。

**A3. 长文/视频速读**
- 痛点：收藏一堆「稍后读」，永远不读。
- 形态：丢链接/粘贴长文 → Agent 抓取正文 → 输出结构化笔记（TL;DR、要点、反对意见、值得记住的 3 句话），存为 Artifact 进知识库（C1）。
- Agent 角色：fetch_url + 摘要；视频先做字幕文本，不做视频理解。
- 底座关系：fetch_url Tool（docs/6 §6.2 已规划）；笔记=report Artifact；是 ChatBot 的一个快捷指令而非独立页面。
- 量级：S–M。不确定性：部分站点反爬/付费墙；视频字幕获取依赖平台 API。

### 簇 B · 沟通与文书（对应 P2）

**B1. 周报/月报生成器**
- 痛点：周五写周报，回忆一周做了什么比干活还累。
- 形态：汇聚数据源（Git commit 历史、平台内 Run/Artifact 记录、手动补录的几行 bullet）→ 生成结构化周报草稿 → 富文本编辑器精修 → 导出。
- Agent 角色：聚合+归纳 Agent；用户做「确认与润色」而非「从零写」。
- 底座关系：复用 DeepResearch 的报告 Artifact + TipTap 编辑器（docs/6 §6.5）；Git 数据源对 Coding Agent 项目免费获得；定时生成（每周五 17:00 出草稿）。
- 量级：M。不确定性：外部数据源（公司 GitLab/日历）集成是边界外工作，v1 只接平台内数据 + 手动补录。

**B2. 会议纪要 Agent**
- 痛点：开完会没人写纪要，行动项靠记忆。
- 形态：上传录音 → 转写（ASR）→ 纪要（决议/行动项/责任人/截止时间）→ 行动项可一键转入任务清单（D4）。
- Agent 角色：ASR（外部 API 或本地 whisper）+ 结构化抽取。
- 底座关系：音频文件=Artifact（media 类型，练音频处理）；纪要=report Artifact；长任务走 Run+SSE 进度。
- 量级：L（ASR 依赖是主要成本）。不确定性：ASR 成本与准确率；隐私（录音含他人声音）；多人说话人分离难度高，v1 可不做。

**B3. 难写消息助手**
- 痛点：拒绝人、催款、谈薪、道歉——这类消息反复改十遍。
- 形态：描述情境 + 想要的态度（坚定/委婉/正式）→ 生成 3 个版本 + 每版的语气说明 → 选中后可继续对话微调。
- Agent 角色：纯生成，ChatBot 特化 prompt。
- 底座关系：几乎是零新基建——ChatBot 预设 prompt 库（docs/6 §8.3）的一个条目。
- 量级：S。不确定性：低；风险是「太薄」，建议作为预设而非独立功能。

### 簇 C · 个人知识管理（对应 P3）

**C1. 第二大脑（个人知识库 RAG）**
- 痛点：笔记、收藏、A3 速读笔记、研究报告散落在各处，「我记得存过但找不到」。
- 形态：统一知识库（导入 Markdown/网页剪藏/A3 笔记/DeepResearch 报告）→ 向量化 → 对话式问答（带出处）→ 问答结果可存回知识库。
- Agent 角色：RAG 检索 + 引用回答； embedding 管线。
- 底座关系：新增向量存储（pgvector，Postgres 原生扩展，不引入新服务——符合「不加依赖」传统）；问答=ChatBot 的一个知识库模式；所有存量 Artifact 自动入库。
- 量级：L（检索质量调优是无底洞，MVP 可控）。不确定性：embedding 成本；检索质量需要真实数据迭代。

**C2. 收藏夹自动整理**
- 痛点：浏览器收藏/稍后读几百条，从未分类。
- 形态：导入收藏导出文件/批量贴链接 → Agent 抓取标题摘要 → 自动打标签、去重、按主题聚类 → 输出整理报告 + 可导入知识库。
- Agent 角色：批量 fetch + 分类聚类。
- 底座关系：批量任务=一个 Run 多子任务（复用 DeepResearch 的并行编排）；结果=report Artifact + C1 入库。
- 量级：S–M（C1 之后）。不确定性：低，可视为 C1 的导入器。

**C3. 读书笔记 → 记忆卡片**
- 痛点：书读完就忘，划线笔记从未复习。
- 形态：书摘/笔记导入 → Agent 生成问答式记忆卡片（间隔重复）→ 每日推送几张到晨报（A1）复习。
- Agent 角色：卡片生成 + 简化版 SM-2 调度（确定性算法，非 AI）。
- 底座关系：卡片=新 Artifact 类型；推送走 A1 晨报通道；复习交互=GenUI 卡片翻转。
- 量级：M。不确定性：间隔重复是独立产品领域，做深会偏离平台主线——建议 v1 只做「生成卡片 + 晨报塞复习」，不做完整 Anki。

### 簇 D · 生活事务（对应 L1/L2/L5）

**D1. 到期哨兵（证件/合同/订阅/保修）**
- 痛点：护照过期、保险断缴、域名忘续费——低频但每次都代价高。
- 形态：登记事项（拍照识别或直接填写名称+到期日）→ 到期前 N 天分多级提醒（进晨报/会话）→ 续期后更新。
- Agent 角色：AI 只负责「拍照/截图 → 结构化提取到期日」，提醒调度是确定性 cron。
- 底座关系：定时检查=A1 基础设施；图片理解=多模态模型调用；提醒卡片=GenUI。
- 量级：S–M。不确定性：低；这是「AI 做录入、确定性做提醒」的正确分工范例。

**D2. 订阅扣费审计**
- 痛点：每月被不知道什么时候开的自动续费扣钱。
- 形态：上传信用卡/支付账单（CSV/截图）→ 识别 recurring 扣费 → 列出「活跃订阅清单 + 年化成本 + 疑似僵尸订阅」→ 用户标记处理后生成取消指引。
- Agent 角色：账单解析 + 模式识别（周期性扣费检测是规则+LLM 混合）。
- 底座关系：账单文件=Artifact（敏感！需加密/本地处理考虑）；结果=report Artifact。
- 量级：M。不确定性：**账单是高度敏感数据**——必须明确「数据不出平台、可一键销毁」策略；支付平台导出格式各异，v1 只支持手动 CSV/截图。

**D3. 购物比价与决策**
- 痛点：买千元以上的东西（耳机/显示器/机票），比价做功课两小时起步。
- 形态：输入需求 + 预算 → DeepResearch 特化流程：候选清单 → 对比表（GenUI Table）→ 给出推荐与理由 → 用户追问「A 和 B 的具体差异」。
- Agent 角色：复用 DeepResearch 全链路，只是领域 prompt 不同。
- 底座关系：几乎零新基建（DeepResearch + GenUI Table + SearchResults）。
- 量级：S（DeepResearch 完成后）。不确定性：价格时效性差（抓到的价格可能过期）；电商反爬严重——定位为「研究助理」而非「实时比价引擎」，价格标注抓取时间。

**D4. 家庭/个人共享清单**
- 痛点：购物清单、待办、分工靠微信吼，漏事。
- 形态：对话式管理清单（「把牛奶加进购物清单」「这周末的待办有哪些」）+ 到期提醒。
- Agent 角色：自然语言 → 结构化清单操作（function calling 的经典场景）。
- 底座关系：清单=轻量实体；提醒=D1 基础设施。
- 量级：M。不确定性：**多人协作违反平台「不做多人协作」既定取舍**——v1 只做个人清单；另外这类工具成熟替代品极多，差异化存疑，优先级低。

### 簇 E · 职业成长（对应 P4）

**E1. 面试准备教练** ⭐（本仓库用户当下真实痛点）
- 痛点：准备面试时资料散落（本仓库就有 `coding-fundamentals-prep/`、`design-interview-prep/`、《DeepWisdom全栈工程师面试备战指南.md》），背诵无反馈、模拟无对手、薄弱点无追踪。
- 形态：
  - 知识库问答：把备战资料灌入 C1 知识库，随时问「SSE 断线重连怎么答」；
  - 模拟面试：Agent 扮演面试官（可指定公司风格/岗位），多轮追问，结束后按维度评分 + 指出知识缺口；
  - 薄弱点追踪：每次模拟/问答的弱点记入档案，晨报（A1）推送针对性复习卡片（C3 复用）。
- Agent 角色：RAG 问答 + 角色扮演 + 结构化评分（评分 rubric 进 prompt，输出结构化 JSON）。
- 底座关系：C1 知识库 + ChatBot 多轮 + GenUI 评分卡片 + A1 复习推送——**几乎是全平台能力的综合演练**，同时直接服务用户当下目标。
- 量级：M（C1 之后）。不确定性：评分的主观性——定位为「陪练与查漏补缺」，不宣称能预测面试结果。

**E2. 简历/作品集优化**
- 痛点：简历写完没人帮看，投出去没回音不知道问题在哪。
- 形态：上传简历 PDF/Markdown + 目标 JD → 逐条匹配度分析 + 改写建议（量化成果、关键词对齐）→ 富文本编辑器内直接改。
- Agent 角色：文档解析 + 对比分析 + 改写。
- 底座关系：resume=Artifact，编辑器复用 TipTap；JD 分析复用 DeepResearch 检索（查目标公司技术栈）。
- 量级：S–M。不确定性：低；与 E1 天然组合（简历过关 → 面试准备）。

**E3. 学习计划 Agent**
- 痛点：想学新技术（如 Rust），教程收藏一堆，从哪开始、怎么验证学会了，没有结构。
- 形态：目标 + 当前水平 + 可用时间 → 生成分阶段学习计划（里程碑+资源+自测题）→ 每周晨报跟进进度 → 自测题对话批改。
- Agent 角色：计划生成（结构化输出）+ 出题/批改。
- 底座关系：计划=report Artifact（可编辑调整）；跟进=A1 通道；批改=ChatBot。
- 量级：M。不确定性：与 E1 有重叠（面试准备=特化的学习计划），可共用「计划+跟进+测验」骨架。

### 簇 F · 开发者日常（对应 P5）

**F1. PR Review Agent**
- 痛点：自己写的代码没人 review；看别人 PR 耗时。
- 形态：指向一个分支/PR/diff → Agent 按维度审查（正确性/安全/风格/测试覆盖）→ 输出结构化意见 → 可对话追问。
- Agent 角色：代码理解 + 规则检查；仓库已有 `pr-review` skill 的雏形思路。
- 底座关系：Git 集成是现成能力（平台管理 Git）；review 报告=Artifact；可作为 Coding Agent 的 Reviewer 角色（docs/5 §4.2 方向一）的用户侧出口。
- 量级：M。不确定性：大 diff 的上下文窗口限制（需分片策略）；误报率需要 rubric 约束。

**F2. 依赖升级影响分析**
- 痛点： renovate/dependabot 提了升级 PR，changelog 几百条，不知道敢不敢点合并。
- 形态：输入「包名 + 从版本 A 到 B」→ Agent 检索 changelog/迁移指南/issue → 输出「破坏性变更清单 + 影响面评估 + 迁移步骤」。
- Agent 角色：DeepResearch 特化 + 结合项目源码做影响面分析（搜代码里的 API 使用点）。
- 底座关系：DeepResearch + Coding Agent 的源码读取；报告=Artifact。
- 量级：S–M。不确定性：changelog 质量参差，幻觉风险需引用体系兜底。

**F3. 报错日志诊断**
- 痛点：贴一坨日志到处搜，StackOverflow 答案过时。
- 形态：粘贴日志/截图 → Agent 定位关键错误行 → 结合知识库（C1）与检索给出「最可能原因 + 修复路径 + 类似案例」。
- Agent 角色：日志解析（规则）+ 检索 + 推理。
- 底座关系：ChatBot 快捷指令 + SearchResults；图片日志=多模态。
- 量级：S。不确定性：低，但差异化弱（通用 ChatBot 也能做）——价值在「与个人知识库联动」（这个错我上次怎么修的）。

**F4. 技术选型对比**
- 痛点：「PG vs SQLite」「Next vs Remix」类问题，每次重新调研。
- 形态：DeepResearch 的领域模板：固定输出「维度对比表 + 决策树 + 你的场景推荐」。
- Agent 角色：DeepResearch 特化。
- 底座关系：零新基建（DeepResearch + GenUI Table）。
- 量级：S。不确定性：低；本质是预设 prompt + 输出模板。

## 3. 评分与筛选

### 3.1 评分维度（1–5 分，5 最高）

| --- | --- |

## 4. 推荐 Shortlist（4 个）

### 4.1 E1 面试准备教练（22 分）— 第一优先

理由：**这是唯一一个「用户自己就是目标用户且当下就在痛」的候选**。仓库里躺着三门面试备战资料就是证据。它同时是 C1 知识库、ChatBot 多轮、GenUI 评分卡、A1 复习推送的综合验收场——做出来之日，平台大部分底座都被真实使用了一遍。注意划清边界：定位「陪练+查漏补缺」，不做「押题/保过」宣称。

### 4.2 C1 第二大脑（21 分）— 底座级优先

理由：它是 E1、C2、C3、A3、F3 的公共依赖，pgvector 不引入新服务符合「不堆依赖」传统。RAG/embedding 是当前技能矩阵（docs/6 §8.4）里的空白格。MVP 边界：先只做 Markdown/报告 Artifact 入库 + 对话问答带出处，网页剪藏往后放。

### 4.3 A1 个人晨报（19 分）— 高频黏性 + 新基建

理由：每天一次的打开理由，是个人平台最难获得的「日常习惯位」。它带来唯一的新基础设施——**定时触发 Run**，而 D1、B1、A2、C3 全都等着复用它。订阅源管理 UI 从简：配置文件式源列表即可。

### 4.4 D1 到期哨兵（18 分，成本最低）— 小而完整

理由：实现量最小但闭环最完整（录入→调度→提醒→销项），是「AI 做感知、确定性做调度」分工哲学的最佳演示，也是定时基建的第一个消费者。多模态录入（拍证件/合同提取日期）顺带点亮多模态技能点。

**Shortlist 排期逻辑**：C1（MVP）→ E1 → A1（定时基建）→ D1。前两个互为依赖且服务当下痛点，后两个共享定时基建。B1 周报生成器分值也高（20），但 v1 数据源只能接平台内数据，价值打折，列为第五顺位观察。

## 5. 候选协同：1+1>2 的组合

```text
E1 面试教练
  ├─ 吃 C1 知识库（备战资料入库）
  ├─ 吃 C3 记忆卡片（薄弱点 → 卡片）
  └─ 吃 A1 晨报（每日复习推送 + 模拟面试提醒）

A1 晨报
  ├─ 吃 A3 速读（长文先速读再决定进不进晨报）
  ├─ 喂 C1 知识库（晨报条目自动归档）
  └─ 承载 D1/B1/C3 的所有提醒出口

C1 第二大脑
  ├─ 吃一切 Artifact（报告/笔记/纪要自动入库）
  └─ 喂 F3 日志诊断（「这个错我上次怎么修的」）

D3 比价 / F4 选型 / F2 依赖分析
  └─ 都是 DeepResearch 的领域模板——证明「一个研究引擎，N 个垂直场景」
```

结论：候选不是平行清单，而是一棵**依赖树**——C1（知识库）和定时基建是两个枢纽节点，shortlist 正是围绕它们选的。

## 6. 反建议：明确不做的方向

| 方向 | 为什么不 |
| --- | --- |
| 通用日历/邮箱/Todo 客户端 | 巨头战场，无差异化；且需要完整新底座，三维筛选只过一维 |
| 多人协作/家庭共享（D4 完整版） | 违反平台「不做多人协作」既定取舍（docs/6 §11），开了就收不回 |
| 反爬对抗型监控（电商价格、抢票、房源） | 法律与稳定性双高风险；D3 已明确降级为「研究助理」 |
| 医疗诊断/投资建议/法律咨询 | 责任风险不可控；L3「文件看不懂」只做「解释+提示注意点」，明确不做建议 |
| 完整 Anki/间隔重复系统 | 独立产品领域，C3 只取「卡片生成+晨报复习」最小环 |
| 视频生成/数字人/语音克隆类 | 与日常痛点无关，纯炫技；且成本与伦理风险高 |
| 移动 App / 微信机器人入口 | 分发渠道工作量大，先让 Web 平台自身成为日常入口 |
