# 功能脑暴 · 第四轮：关系、健康与长期人生系统

> 版本：1.0（脑暴稿，待 review）
> 定位：第四轮脑暴，也是视角最「非技术」的一轮：**AI 作为长期生活系统的陪练**——目标与决策、习惯与复盘、关系维护、身心记录（谨慎区）。前序：[7](./7-功能脑暴.md)（信息/知识/职业/事务）、[8](./8-功能脑暴-创作与表达.md)（创作表达）、[9](./9-功能脑暴-自动化与数字资产.md)（自动化/数字资产）。
> 纪律不变；本轮额外加一条纪律：**凡是触碰身心的候选，红线先行**——记录与观察可以，诊断与建议不做。

---

## 0. 本轮视角说明

前三轮的痛点大多是「效率问题」。这一轮的痛点是「**长期主义失败**」——人都知道自己想要什么，但系统性地做不到：

```text
长期主义痛点地图
─────────────────────────────────────────────────────────
N1 目标年年立年年废：新年计划活不过三月，
   不是不想做，是没有节奏、没有复盘、没有人问
N2 决策无复盘：换工作/买房/大额消费，做决定时
   理由充分，三年后从不知道当初的假设对不对
N3 习惯坚持难：健身/读书/早起，全靠意志力，
   缺外部节奏与「断档预警」
N4 关系靠记忆：重要的人生日、上次联系是半年前、
   答应过的事——不是不在乎，是没系统
N5 送礼焦虑：一年五六次，每次临时抱佛脚两小时
N6 身心数据看不懂：手表记录了睡眠/运动/心率，
   数据在，洞察没有；情绪起伏也从无记录
N7 人生素材散落：重要时刻、成长轨迹、想说给未来
   的话——没有容器，更别说「数字遗产」
─────────────────────────────────────────────────────────
横切痛点 W：这些痛点的解药不是更强的 AI，而是
   「记录 → 节奏 → 复盘」的循环——AI 的角色是降低
   记录摩擦、提供节奏、主持复盘，而不是替你做人生决定。
```

## 1. 候选功能池（11 个）

### 簇 P · 目标、决策与习惯（对应 N1/N2/N3）

**P1. 决策日志** ⭐
- 痛点：重大决策从不复盘，同样的认知偏差反复犯（N2）。
- 形态：做决定时花 3 分钟记录（决策/理由/预期结果/复盘日期）→ 到期晨报提醒复盘 → 「当时预期 vs 实际」对照记录 → 年度决策回顾（我的预测准确率、反复出现的偏差模式）。
- Agent 角色：记录时帮你「逼问」（这个决策可逆吗？最坏结果是什么？）+ 复盘时的模式归纳。
- 底座关系：决策=轻量实体；提醒=定时基建；年度回顾=docs/8 J1 年报的一个章节。**这是全部 52 个候选里「AI 含量最低但认知价值最高」的设计之一**——AI 只是记录员和主持人。
- 量级：S–M。不确定性：几乎没有；唯一风险是用户不记——所以录入必须 <3 分钟。

**P2. 个人 OKR/目标教练**
- 痛点：目标废于无节奏（N1）。
- 形态：年度目标 → Agent 协助拆解为季度/月度里程碑（可编辑确认）→ 每周晨报检查点：「这周为目标做了什么」→ 连续缺位预警 → 季度复盘对话。
- Agent 角色：拆解建议 + 复盘主持（追问式对话）；进度判定基于用户自述+关联 Artifact（如「读完 X 本书」可关联读书笔记）。
- 底座关系：目标=轻量实体；节奏=定时基建+晨报；复盘=ChatBot 多轮。
- 量级：M。不确定性：与 docs/7 E3 学习计划共享「计划+跟进+复盘」骨架，应合并设计。

**P3. 习惯追踪 + 断档预警**
- 痛点：习惯靠意志力（N3）。
- 形态：打卡（输入框一句话/一键）→  streak 与趋势图卡 → 断档 2 天晨报温和提醒 → 月度习惯报告。
- Agent 角色：几乎为零——打卡与统计是确定性；AI 只在月度报告里做模式观察（「你的健身总是断在出差周」）。
- 底座关系：打卡=轻量实体；提醒=定时基建；图卡=GenUI Chart。
- 量级：S。不确定性：成熟替代品多（各类打卡 App）——差异化在「与其他系统的联动」（读书打卡自动关联读书笔记），单独做价值平庸。

### 簇 Q · 关系维护（对应 N4/N5）

**Q1. 个人关系 CRM**
- 痛点：重要关系靠记忆维护（N4）。
- 形态：重要的人档案（生日/纪念日/上次联系/承诺过的事/喜好笔记）→ 提醒（生日前一周+「和小王三个月没联系了」）→ 联系后一句话记录 → 年度关系回顾。
- Agent 角色：对话式录入（「周六和大学同学吃饭，聊到他想换工作」→ 结构化到人物档案）；提醒与回顾确定性。
- 底座关系：人物档案=轻量实体；提醒=定时基建；**隐私等级最高的一档**（他人信息），需显式声明数据边界。
- 量级：M。不确定性：录入坚持度；以及「关系被系统化」本身有人抵触——定位「备忘录」，不是「监控」。

**Q2. 礼物推荐 Agent**
- 痛点：送礼临时抱佛脚（N5）。
- 形态：对象档案（Q1 的喜好笔记）+ 场合 + 预算 → DeepResearch 候选研究 → 3–5 个方案（理由+链接+价格区间）→ 送出后记入档案（明年不重复）。
- Agent 角色：DeepResearch 特化 + 档案读写。
- 底座关系：Q1 档案 + DeepResearch + GenUI 卡片；零新基建。
- 量级：S（Q1 之后）。不确定性：低；频次低但每次价值高。

**Q3. 社交复盘（周报式）**
- 痛点：一周结束说不清自己社交能量花在哪。
- 形态：并入 Q1 的一句话记录 → 每周晨报卡片：联系了谁/多久没联系的重要的人/社交-独处节奏。
- Agent 角色：模式观察。
- 底座关系：Q1 附属，不独立。
- 量级：S。不确定性：与 Q1 合并即可，不单列。

### 簇 R · 身心记录（对应 N6，红线区）

**R1. 健康数据洞察（非医疗）**
- 痛点：手表数据无洞察（N6）。
- 形态：手动导出/截图健康数据 → 趋势可视化 + 模式观察（「最近三周睡眠中位数下降 40 分钟，与出差周重合」）→ 月报。
- Agent 角色：数据分析 + 模式描述。
- 底座关系：数据=Artifact；图卡=GenUI Chart；**红线写进产品文案：不提供任何医疗建议，异常只提示「建议咨询专业人士」**。
- 量级：M。不确定性：健康平台数据导出格式碎片化；以及「观察」与「建议」的措辞边界需要仔细把关。

**R2. 饮食随手记**
- 痛点：想知道自己吃得怎么样，但热量 App 录入太累。
- 形态：拍照/一句话 → 大致营养估算（明确标注「粗略」）→ 一周回顾（蛋白质够吗/蔬菜够吗/外食占比）。
- Agent 角色：多模态食物识别 + 估算。
- 底座关系：图片=Artifact；周报=晨报通道。
- 量级：M。不确定性：估算误差大，预期管理为「结构观察」而非「热量精确」；不做减肥/饮食建议。

**R3. 情绪日记（非心理干预）**
- 痛点：情绪起伏无觉察（N6 与 docs/8 J3 同族）。
- 形态：与 docs/8 J3 日记复盘合并设计——一句话情绪标记 + 周/月模式观察。
- Agent 角色：模式观察；**红线：不做心理状态评估、不做干预建议、检测到低落模式时只提供通用求助资源信息**。
- 底座关系：见 docs/8 J3。
- 量级：S（J3 之后）。不确定性：隐私与红线文案是主要工作量。

### 簇 S · 人生档案（对应 N7）

**S1. 人生档案/时间胶囊**
- 痛点：重要时刻与「想对未来的自己说的话」没有容器（N7）。
- 形态：里程碑记录（事件+照片+当时想法）→ 时间胶囊（写给 1/5/10 年后的自己，到期晨报解锁）→ 人生时间线可视化。
- Agent 角色：几乎为零——仪式感与容器是核心，AI 只做年度回顾时的叙事串联。
- 底座关系：档案=Artifact（特殊保留策略：永不清理）；时间线=GenUI 长页。
- 量级：S–M。不确定性：低频但情感价值独特；与 docs/8 J1 年报天然联动。

**S2. 数字遗产清单**
- 痛点：如果自己出事，家人不知道账号/资产/重要文件在哪（N7 的终极形态）。
- 形态：结构化清单（有什么账号/资产/文件、在哪、不存凭据本身）+ 年度更新提醒 + 紧急联系人指引文档。
- Agent 角色：引导式盘点（「你的域名在哪注册？续费了吗？」对话式补全）。
- 底座关系：清单=最高加密等级 Artifact；提醒=定时基建。
- 量级：S–M。不确定性：**安全模型必须单独设计**（加密、访问控制、本人验证）；话题沉重但真实，是个人平台「陪用户足够久」之后自然会到的功能。

## 3. 推荐 Shortlist（3 个）

1. **P1 决策日志（19 分，但认知价值/成本比全场最高）**：3 分钟录入 + 定时复盘 + 年度偏差报告，几乎是纯确定性系统加一个会「逼问」的 Agent。它是「AI 不替你做决定，但让你成为更好的决策者」这一产品哲学的化身——面试时这也是最好的故事。
2. **P2 目标教练（20 分）**：「计划→节奏→复盘」骨架与 docs/7 E3 学习计划、E1 面试教练**三合一**——它们本质是同一个「目标系统」的三个皮肤，应统一设计。这轮把这一点说透，比功能本身更重要。
3. **Q1 关系 CRM（18 分）**：痛点真实（N4 几乎人人中招），录入摩擦被对话式录入大幅压低；隐私边界清晰声明后可做。Q2 礼物推荐作为其自然延伸，不单独排期。

观察项：S2 数字遗产（等安全模型专项设计）、R 簇全部（红线文案与隐私设计先行，不排期）。

## 4. 四轮脑暴的总协同图

```text
                 ┌──────────────────────────────┐
                 │  枢纽一：C1 知识库（RAG）      │
                 │  ← 一切 Artifact/截图/笔记/资料 │
                 └───────────────┬──────────────┘
                 ┌───────────────┴──────────────┐
                 │  枢纽二：定时基建（cron→Run）  │
                 │  ← 晨报/提醒/复盘/监控/自动化  │
                 └───────────────┬──────────────┘
                                 │
        四轮 shortlist 全部挂在两个枢纽上：
        R1: E1 面试教练  C1 大脑   A1 晨报   D1 到期哨兵
        R2: G2 演示稿    G1+G4 创作管线      J1 年报
        R3: K2 截图管家  L1 记账   L2 发票   M1 自动化(泛化枢纽二)
        R4: P1 决策日志  P2 目标教练         Q1 关系 CRM
                                 │
                 ┌───────────────┴──────────────┐
                 │  「目标系统」统一骨架：        │
                 │  E1 面试 / E3 学习 / P2 OKR   │
                 │  共用 计划→节奏→复盘→测验      │
                 └──────────────────────────────┘
```

四轮累计 **52 个候选**，收敛出两条元结论：

1. **两个枢纽决定一切**：知识库（RAG）与定时基建的优先级高于任何单一功能，它们每完成一分，候选池就便宜一分。
2. **一个统一骨架反复出现**：「计划→确认→执行→节奏→复盘」——Coding Agent 的 Contract 审批、DeepResearch 的计划门、G1 创作管线、P2 目标系统，全是同一骨架的化身。平台真正的产品语言不是「三个功能」，而是这一个循环。

## 5. 反建议（本轮）

| 方向 | 为什么不 |
| --- | --- |
| 任何医疗/心理诊断与建议 | 红线。R 簇只做记录与模式观察，文案层面终身设防 |
| 社交关系量化打分/排名 | 异化关系、伦理反感；Q1 定位备忘录 |
| 意志力替代型「强制」功能（锁手机等） | 平台形态够不着，且与用户为敌的设计不持久 |
| 减肥/饮食/投资建议 | 同红线；R2/L3 只做结构观察 |
| 为低频功能建专用新基建 | 本轮候选必须 100% 复用既有枢纽，否则不做——这是本轮自我施加的最严约束 |

## 6. 下一步（四轮脑暴收口建议）

1. **冻结总池**：将四轮 52 个候选合并为一张总优先级表，review 后冻结；此后新想法按 §2 卡片格式先入池、攒批再评，防止主线漂移。
2. **建议的总排期逻辑**（供 review，非承诺）：
   - 主线不变：docs/6 四期（ChatBot→GenUI→DeepResearch→整合）；
   - 第一扩展包：C1 知识库 + E1 面试教练（当下真实痛点，RAG 技能）；
   - 第二扩展包：定时基建 + A1 晨报 + M1 自动化泛化（顺手带出 D1/P1/P2 的提醒骨架）;
   - 第三扩展包：K2 截图管家 + L1 记账（多模态与结构化录入）；
   - 彩蛋位：J1 年报、G2 演示稿穿插在对应基建成熟后。
3. **两个专题评估**值得单独成文：「本地伴侣进程」（docs/9 K1 逼出）与「敏感数据分级策略」（账单/健康/关系/遗产四类候选的共同前置）。
4. 四轮脑暴到此覆盖：信息、知识、职业、事务、创作、表达、自动化、资产、目标、关系、身心、人生档案——**建议收手**。脑暴边际收益已递减，下一轮同类练习应转为「对 shortlist 做深度评估」而非继续发散。
